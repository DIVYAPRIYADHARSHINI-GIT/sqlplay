Root cause: the host's Python SQLite build compiles extension loading out, omitting the Python method. Local Homebrew SQLite provides that method.
Fix: call it only when present; absence already means extension loading is unavailable, and the SQL authorizer still denies load_extension. Added a simulated no-extension-build regression test. Also changed /health to execute SELECT 1 through the actual restricted connection and added a failing-health regression test; the old metadata-only health check did not cover execution readiness.

The verifier now handles non-JSON error bodies and writes partial JSON progress after each check. The frontend API wrapper now supplies friendly text for a non-JSON response, with five new unit tests for success, validation, network, timeout and malformed response handling.
